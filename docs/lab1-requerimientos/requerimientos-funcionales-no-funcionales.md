# Laboratorio 1 - Requerimientos funcionales y no funcionales

## Proyecto
Khanauky

## Descripción

Khanauky es un sistema orientado a apoyar la gestión de pedidos, clientes, producción, almacén y control de stock de una empresa dedicada a la producción y venta de agua tratada y hielo.

A partir de las necesidades identificadas en el proceso del negocio, se definen los siguientes requerimientos funcionales y no funcionales.

---

## Requerimientos funcionales

| ID | Tipo | Descripción |
|---|---|---|
| RF-01 | Funcional | El sistema debe permitir registrar y consultar información de los clientes. |
| RF-02 | Funcional | El sistema debe permitir registrar pedidos indicando el cliente, los productos y las cantidades solicitadas. |
| RF-03 | Funcional | El sistema debe permitir consultar y actualizar el stock disponible de los productos. |
| RF-04 | Funcional | El sistema debe permitir registrar y consultar información de producción asociada a los pedidos. |
| RF-05 | Funcional | El sistema debe permitir consultar las existencias y registrar las salidas de almacén asociadas a los pedidos. |
| RF-06 | Funcional | El sistema debe permitir consultar y actualizar el estado de los pedidos. |

---

## Requerimientos no funcionales

| ID | Tipo | Descripción |
|---|---|---|
| RNF-01 | No funcional - Usabilidad | El sistema debe presentar una interfaz clara y comprensible que permita al personal registrar y consultar información sin requerir capacitación especializada. |
| RNF-02 | No funcional - Seguridad | El sistema debe permitir el acceso a la información únicamente a usuarios autorizados según las funciones que realizan dentro del negocio. |
| RNF-03 | No funcional - Confiabilidad | El sistema debe conservar la consistencia de la información de pedidos y stock durante las operaciones de registro y actualización. |
| RNF-04 | No funcional - Disponibilidad | El sistema debe mantener una disponibilidad mínima del 95 % durante el horario habitual de operaciones del negocio. |

---

## Diferencia entre requerimientos funcionales y no funcionales

Los requerimientos funcionales indican las acciones que el sistema debe realizar, por ejemplo registrar un pedido o actualizar el stock.

Los requerimientos no funcionales establecen cualidades, restricciones o condiciones relacionadas con la forma en que el sistema debe funcionar, como seguridad, usabilidad, confiabilidad y disponibilidad.

---

## Resultado

Se identificaron seis requerimientos funcionales y cuatro requerimientos no funcionales para Khanauky.

Estos requerimientos constituyen una base inicial para continuar con la elicitación, análisis, modelado y trazabilidad en los siguientes laboratorios.

## Convención de identificadores

En los Laboratorios 1 al 5 se utiliza la nomenclatura RF-01, RF-02, etc., para identificar los requisitos funcionales.

En la documentación posterior de trazabilidad del proyecto se utiliza la nomenclatura REQ-001, REQ-002, etc.

La equivalencia utilizada es:

|---|---|
| RF-01 | REQ-001 |
| RF-02 | REQ-002 |
| RF-03 | REQ-003 |
| RF-04 | REQ-004 |
| RF-05 | REQ-005 |
| RF-06 | REQ-006 |
