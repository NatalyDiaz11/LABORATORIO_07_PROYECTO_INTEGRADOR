# Checklist de consistencia - Laboratorio 3

## Proyecto
Khanauky

Antes de cerrar el Laboratorio 3 se revisó la consistencia entre requisitos, actores, casos de uso, diagramas de actividad e interfaces del sistema.

## Checklist

- [x] Todos los actores identificados aparecen relacionados con uno o más casos de uso.
- [x] Los casos de uso principales están relacionados con necesidades reales del sistema Khanauky.
- [x] Se documentaron al menos tres casos de uso de forma completa.
- [x] Los casos de uso incluyen precondiciones, postcondiciones, flujo principal, excepciones y reglas de negocio.
- [x] Las reglas de negocio están relacionadas con los casos de uso correspondientes.
- [x] Se elaboró un diagrama general de casos de uso.
- [x] Se elaboraron al menos dos diagramas de actividad.
- [x] Los diagramas de actividad representan decisiones y excepciones del flujo.
- [x] Las interfaces reales del sistema fueron relacionadas con casos de uso mediante identificadores UI-CU.
- [x] Las evidencias de interfaz se encuentran almacenadas en el repositorio.
- [x] Se mantiene consistencia entre los nombres e identificadores utilizados en la documentación.

## Resultado de la revisión

La revisión permitió comprobar que los principales artefactos desarrollados durante el Laboratorio 3 mantienen relación entre sí.

Los requisitos previamente identificados permiten definir los casos de uso, los casos de uso se representan mediante diagramas y varias de estas funcionalidades cuentan con evidencia dentro de la interfaz real del sistema Khanauky.

## Conclusión

El modelado de casos de uso permite representar de manera estructurada cómo interactúan los actores con el sistema y facilita comprobar que las funcionalidades documentadas tienen correspondencia con el funcionamiento real de Khanauky.
